# TMS IDE (Vue)

Web IDE на Vue 3 для сборки SVG-мнемосхем SCADA и экспорта пары
`view.svg` + `animations.json` для WebScada-рантайма.

## Стек

- **Vue 3.5** (Composition API, `<script setup>`)
- **Pinia 4** — state management
- **Vite 8** (Rolldown) — build / dev
- **PrimeVue 4** (Aura, primary cyan) — UI kit
- **Tailwind CSS 4** (CSS-first, плагин `@tailwindcss/vite` — конфиг-файлов нет) — layout / utility
- **@joint/core 4** (JointJS) — SVG-редактор
- **fflate** — ZIP-экспорт/импорт проекта архивом
- **interactjs** — drag/resize/снап примитивов в редакторе символов
- **@vueuse/core** — listener'ы/observer'ы с auto-cleanup
- **Vitest 4 + jsdom + @vue/test-utils 2** — unit- и компонентные тесты
- **Electron 43 + electron-builder** — портативная десктоп-сборка (см. ниже)

## Запуск

Нужна **Node 22.22+ / 24.15+** (планку задаёт jsdom 30 в тестах; проверяется через
`engines` в package.json).

```bash
npm install
npm run dev       # http://localhost:5174/
npm run build     # production-сборка в dist/
npm test          # тесты однократно
npm run lint      # eslint
npm run format:check  # prettier
npm run knip      # неиспользуемые экспорты
```

Десктоп-сборка (см. «Портативная сборка» ниже):

```bash
npm run desktop:preview # собрать статику и открыть окно приложения (аналог vite preview)
npm run desktop:smoke  # проверка: окно поднялось, IndexedDB работает (для CI)
npm run desktop:build  # portable .exe → ../release-tms/
npm run desktop:build:linux  # AppImage (нужен Linux-раннер)
npm run icon:build     # public/favicon.svg → build/icon.png (при смене логотипа)
```

CI (GitHub Pages, `.github/workflows/deploy.yml`) на каждый push в `main` гоняет
`format:check` → `lint` → `test` → `knip` → `build`, поэтому любой из этих шагов
валит деплой.

## Браузеры

Работает в любом современном браузере: открытие проекта и загрузка tag-list'а идут
через File System Access API там, где он есть, и через обычный `<input type="file">`
там, где нет (Brave отключает FSA по умолчанию, в Firefox и Safari пользовательских
пикеров нет). Единственная разница — tag-list: с FSA он тихо перечитывается из файла
при старте, без FSA список тегов поднимается из сохранённой копии, а подтянуть
изменения из файла можно кнопкой «Tag-list». Выгрузка `.zip` везде идёт скачиванием.

## Модель символа

> В интерфейсе сущность называется **«символ»** (палитра, инспектор, редактор); в
> коде и формате проекта — `stencil` (`stencilId`, `definitions/`, `library/`).

Каждый символ — папка в `src/stencils/definitions/<id>/`:

- `stencil.json` — id, label, category, size, ports + опционально slots,
  animationTemplate, `states` (анимация «по значению»), `stateColors` (цвет
  символа по состоянию: строка = контур или `{stroke, fill}`), `portSeq` (счётчик
  выданных имён портов), `minWidth` (cell_bus), `params` (правимые подписи)
- `shape.svg` — SVG c атрибутами `data-anim-suffix` на анимируемых элементах,
  `data-tms-param` на правимых подписях и
  классом `tms-state-fill` на заливаемых фигурах stateful-символа (по нему цвет
  состояния красит заливку; контуры красятся каскадом)

Формат файлов под git фиксирован: `shape.svg` — без xml-декларации, с одним
завершающим переводом строки и без пустых групп; нулевой `portSeq` в json не пишется.
Иначе файлы «дышали» бы в диффах между двумя писателями (редактор и импорт `.zip`).

Реестр строится автоматически (Vite glob), перезапуск не нужен.

Имя порта (`ports[].name`) — **вечный ключ**: по нему провод держится за порт, и оно
уезжает в экспортный `view.svg`. Поэтому имена не переименовываются и не
переиспользуются — номер нового порта выдаёт счётчик `portSeq`, а не длина списка (иначе
имя удалённого порта досталось бы новому, и провод на другой форме сел бы не туда).
Порядок и сторону порта видно в редакторе, в имени они не кодируются.

### Слоты

```json
{
  "key": "onoff",
  "type": "Boolean"
}
```

Только `key` обязателен; `type` опционален. В `animationTemplate.bindings.tag` —
placeholder `{slot.KEY}`. При экспорте подставится выбранный тег. Слот без
значения → биндинг отбрасывается.

Picker слота фильтрует теги по `type`: булевы слоты (`type: Boolean`) — только
bool-теги из tag-list (по типу, не по суффиксу имени). Слот `value` (анимация «по
значению») — без фильтра (сигнал может быть кодом/enum).

### Декларативные флаги в stencil.json

Спец-поведение символа объявляется прямо в его JSON — exporter / Inspector /
Canvas читают флаги, никаких хардкод-списков в коде:

| Поле                | Значение                                                                                | Где применяется                             |
| ------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------- |
| `quality: true`     | эмитит range-биндинг `[0,191] → animation-off` на outer                                 | cell_qr / cell_qk / cell_qf                 |
| `static: true`      | без visual-реакции на animation-классы; multi-select пропускает; detailTags не собирает | cell_text                                   |
| `noRotate: true`    | оверлей-кнопки rotate не рендерятся                                                     | cell_text / cell_bus / cell_pi              |
| `noFlip: true`      | оверлей-кнопки flip не рендерятся (поворот при этом доступен)                           | cell_value / cell_text / cell_bus / cell_pi |
| `defaults: { ... }` | merge в `tms` при создании ячейки                                                       | cell_text (`text`)                          |
| `params: [ ... ]`   | правимые на холсте подписи символа (ключ + текст по умолчанию)                          | cell_value (величина, единица)              |

«Булев символ» (свой тег рендерится первой строкой BooleanBlock) выводится
по convention: символ со слотом `key === 'onoff'`. Helper `hasBoolSlot`.

### Символы

Кроме категории у символа есть **область применения** (`domains` в `stencil.json`):
«Энергетика», «Технология», «Сети». Это фильтр-чипы над палитрой, а не подкатегории —
один аппарат может относиться сразу к нескольким областям. Ни один чип не выбран —
показываются все; символ без указанной области виден при любом фильтре, а поиск
работает по всей палитре независимо от чипов. Задаётся в редакторе символов.

| ID         | Категория      | Назначение                                                                                                                       |
| ---------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| cell_bus   | Шины           | Шина (resizable, динамические порты) — единственный нередактируемый символ палитры                                               |
| cell_value | Измерения      | Карточка значения: правимые подписи + значение тега                                                                              |
| cell_text  | Прошлый формат | Подпись прошлого формата (в палитре скрыт: подписи рисуются разметкой, старые конвертируются при открытии)                       |
| cell_node  | Прошлый формат | Точка соединения прошлого формата (в палитре скрыт: точку рисует свободный конец провода, старые узлы растворяются при открытии) |
| cell_tv2   | Трансформаторы | Трансформатор (2 обмотки)                                                                                                        |
| cell_tv3   | Трансформаторы | Трансформатор (3 обмотки)                                                                                                        |
| cell_qw    | Коммутация     | Выключатель (slot.onoff → +/−)                                                                                                   |
| cell_qr    | Коммутация     | Отделитель (slot.onoff → open/closed)                                                                                            |
| cell_qk    | Коммутация     | Короткозамыкатель (slot.onoff)                                                                                                   |
| cell_qf    | Коммутация     | Автоматический выключатель (slot.onoff)                                                                                          |
| cell_alr   | Сигналы        | Аварийный сигнал                                                                                                                 |
| cell_pi    | Измерения      | Счётчик электроэнергии (статичный)                                                                                               |

`cell_bus`, `cell_node` и `cell_text` рендерятся программно: вид задаёт `tms`, а
`shape.svg` остаётся только превью для палитры. Карточка значения (`cell_value`) —
обычный редактируемый символ: полоска, фон и три подписи нарисованы в её `shape.svg`.

### Редактор символов (создание и правка в IDE)

Порядок наложения фигур правится через ПКМ по фигуре (подменю «Порядок») и
`Ctrl+]` / `Ctrl+[` (с Shift — до края): у фигур слой задаёт позиция в массиве, она
же определяет порядок в `shape.svg`, поэтому «нарисовал заливку последней — она
перекрыла контур» лечится без перерисовки.

**Поворот, отражение и удаление выделения** — кнопками вокруг рамки выделения (те же
иконки и места, что на холсте), клавишами `R` / `Shift+R` (поворот на 90°),
`Shift+H` / `Shift+V` (отражение), `Del` и пунктами того же ПКМ-меню. Центр
преобразования — центр общего габарита выделения, поэтому пачка фигур поворачивается
как целое, а не каждая вокруг себя; вся операция — один шаг истории. Кнопка
показывается только когда операция реально меняет картинку: у круга и квадрата
поворот, у прямоугольника и ортогональной линии отражение ничего не дают, у одиночной
подписи поворота нет вовсе (глифы остаются горизонтальными). Тот же гейт закрывает и
клавиши, и пункты меню.

Кнопка «+» в шапке палитры открывает редактор-оверлей поверх холста; пока он
открыт, левая панель и кнопки проекта в топ-баре недоступны (без кликов/фокуса) —
импорт и экспорт не должны идти поверх незакрытого черновика символа; правая панель
(свойства символа) активна.
Рисование примитивов (line / rect / эллипс / polyline / подпись; ломаная замыкается кликом
по стартовой вершине → `polygon`) + расстановка портов **на границе** символа, всё
со снапом к сетке (вершины фигур — 1px, порты и размер — шаг 5); правка /
перемещение / ресайз — через interactjs (колбэки пишут в модель, Vue
перерисовывает). Undo/redo (Ctrl+Z / Ctrl+Y) откатывает и фигуры с портами, и
метаданные символа (подпись, размер холста, режим анимации, состояния, их цвета);
копирование выделенного со всеми свойствами — Ctrl+C / Ctrl+V (буфер переживает
закрытие редактора, т.е. фигуры переносятся между символами). Холст обрамлён
линейками X/Y (деления 10/5/1). На сохранении контент обрезается до bbox
(кратно шагу сетки) и сдвигается в (0,0) — «воздух» холста отбрасывается. **Размер
символа** (Ш×В) правится в тулбаре рядом с инструментами. Правая панель `StencilInspector` —
две плашки: «Символ» (id `[a-z0-9_]` / label / категория, флаги `noRotate` и `noFlip`, анимация
состояния) и «Фигура» (цвет линии / толщина / заливка / скругление + видимость).
Валидация — при сохранении.

**Выделение фигур** — множественное, жестами как на холсте: ЛКМ-drag по пустому месту
(в том числе за пределами символа) тянет рамку, короткий клик снимает выделение,
Ctrl/Cmd добавляет к выделению (и рамкой, и кликом по фигуре), Ctrl+A берёт все
фигуры, Esc снимает выделение и лишь потом закрывает редактор. Захват — по пересечению
габаритов (иначе тонкую линию не поймать); порты рамка не берёт — они выделяются кликом.

**Порты — как элементы.** Клик выделяет порт (Ctrl/Cmd — добавляет к выделению), `Del`
удаляет выделенные одним шагом истории, стрелки двигают их по границе символа шагом
сетки. Выделение портов и фигур взаимно исключающее, поэтому `Del` всегда однозначен.
Прежний жест «повторный клик по порту = удалить» убран: он не совпадал ни с чем другим
в редакторе и срабатывал при попытке порт подвинуть.

**Рисовать можно начиная за пределами символа** — так же, как тянуть рамку выделения.
Жест слушается на всей области просмотра, а координаты прижимает снап (вершины к 1px,
порт проецируется на ближайшую сторону), поэтому фигура не уедет за габарит. Это важно
для символов, чей рисунок занимает весь холст: пустого места, чтобы начать штрих,
внутри просто нет.
Каждая выделенная фигура получает halo-обводку под собой (реальные цвета видны
поверх) толщиной по её же обводке, при нескольких — ещё и общая пунктирная рамка.
Перемещение и удаление работают на всю пачку (снап считается по ведущей фигуре, так
что взаимное расположение не разъезжается), один Ctrl+Z откатывает всю операцию.
Стрелки сдвигают выделение на 1 px, с Shift — на 5 px (шаг портов); у края шаг
обрезается, а не отменяется.
Свойства в инспекторе тоже применяются ко всему выделению — только к тем фигурам, у
которых свойство есть (у линии нет заливки, у эллипса скругления, у подписи ни того
ни другого — но видимость по состоянию есть и у неё);
расходящееся значение показано как «разные» / пустое поле / `indeterminate`-галка.
Ручки ресайза и поля геометрии/текста — только когда выделена одна фигура.

**Подпись: две галки.** У текстового примитива есть «Показывает значение тега» и
«Правится на холсте» (взаимоисключающие — содержимое приходит либо из рантайма, либо
от автора схемы):

- **Показывает значение тега** — символ получает слот `value_text` и text-карточку;
  на схеме такой подписи привязывают тег, а её текст в символе остаётся заглушкой
  (видна в редакторе и до прихода данных). Такая подпись в символе одна.
- **Правится на холсте** — подпись становится **параметром**: в `stencil.json`
  появляется `params: [{ key, default }]`, в `shape.svg` — метка `data-tms-param`, а у
  каждого экземпляра своё значение в `tms.params` (поля в инспекторе холста). Текст в
  символе служит значением по умолчанию и подписью поля. Ключ выдаётся автоматически и
  **помнится при снятии галки**: значения экземпляров лежат под ним, и новый номер
  осиротил бы уже расставленные подписи.

Роль подписи видна у самой фигуры: у показывающей значение тега — серая решётка над
левым верхним углом, у правимой на холсте — пунктир под базовой линией. Пустая подпись —
штатная (например, единица величины, которую вписывают на схеме): она остаётся фигурой и
рисуется иконкой текстового блока; убрать её, как любую другую, — `Del`. Маркеры и
иконка живут только в редакторе, в `shape.svg` не уезжают.

**Анимация состояния** (единый свитч «Выкл / Булево / По значению», один режим за раз):
у выделенной фигуры задаётся видимость по состоянию; на выходе — слот-драйвер +
карточки `animationTemplate`, прячущие группу `animation-hidden` на «чужих» значениях.

- **Булево** — 2 состояния (`.true`/`.false`), слот `onoff`.
- **По значению** — N состояний (`meta.states = { key, label, code }`), слот `value`,
  суффикс группы = стабильный `key`, код (значение сигнала) вписывает автор. Пресет
  подписей + шаблон «Сигнал положения» (Включен/Отключен/Промежуточное/Недостоверно) —
  для разъединителей/отделителей по СТО 56947007.

**Цвет состояния.** У каждого состояния — свотчи «Контур» и «Заливка»
(`meta.stateColors`, строка = только контур либо `{stroke, fill}`). Контур красит
`stroke` всех потомков; заливка (`fill`) — только замкнутые фигуры (rect/circle/
polygon, opt-in класс `tms-state-fill`), поэтому контур/hit-area не заливаются
«блобом», а контурную фигуру можно закрасить в конкретном состоянии (лампа). Свотч
заливки виден лишь при наличии заливаемых фигур. Пусто → состояние меняет только
видимость. На выходе — `stateColors` в stencil.json; exporter вешает класс
`animation-color-<id>-<key>` на outer, CSS перекрашивает потомков. **Обесточивание
(`animation-off`) бьёт цвет** — `:not(.animation-off)` в правиле, т.е. де-энергизация
(напряжение/quality с холста) остаётся серой поверх подсветки состояния.

Превью состояния — плавающий Select слева-сверху на холсте (эмуляция видимости +
цвета, на экспорт не влияет). Чекбокс `quality` (серость + «показать все положения»
при bad-качестве) — в том же блоке анимации, только при включённой анимации.
Де-энергизация (серость по напряжению/качеству) в символе не задаётся — это холст
(`boolSource`/`rangeSource`). Символ регистрируется в реестре сразу (появляется
в палитре) и пишется в `definitions/<id>/` dev-плагином.

Правка — кнопка-карандаш в строке символа (по ховеру, у всех **кроме залоченных**
`locked: true`). Залочены те, чей SVG редактор не воспроизвёл бы без потерь:
программные без `shape.svg` (bus / text / value), с текстом (pi), с нестандартными
атрибутами обводки (alr — скругления), и структурная точка `cell_node`. Коммутация
qw / qr / qk / qf **редактируема** (единый формат `.true` / `.false`). Открывает
редактор с загруженным символом (`parseStencilSvg`
разбирает `shape.svg` обратно в примитивы, порты — из `stencil.json`); id заблокирован
(= имя папки).

**Правка доезжает до расставленных экземпляров.** На сохранении символы на активной
форме подтягивают рисунок, набор и позиции портов и габарит — одной операцией, так что
`Ctrl+Z` откатывает это у всех сразу. Провод следует за портом сам (привязка по имени);
если порт из символа удалили, конец провода **отцепляется** в точку, где порт был —
провод остаётся виден, попадает в выделение, а тост говорит, сколько концов ждёт
перецепки. Формы, закрытые в этот момент, сверяются с библиотекой при открытии (и при
экспорте — в `.zip` уходят формы с портами текущей версии символа). Габарит не трогается
у тех, кому размер задаёт содержимое или ресайз (шина, подпись, значение).

Удаление — кнопка-корзина в строке символа (по ховеру, у всех **кроме залоченных**
`locked`) с ConfirmPopup: снимает из реестра + сносит папку. Если символ расставлен
в формах, удаление отклоняется (не осиротить ячейки), с указанием где.
Разметка чужого символа (импорт .zip) проходит через whitelist тегов и атрибутов
(`utils/sanitizeSvg`) на входе в реестр: `<script>`, обработчики событий, `style`,
внешние ссылки и SMIL вырезаются, о чём пишется предупреждение. Встроенные символы
идут через тот же фильтр — иначе сравнение «изменился ли символ» считало бы их
изменёнными.

Персист: правка/новый символ пишется оверрайдом в IndexedDB (`stencilOverrides`)
и переживает reload и в проде; на старте оверрайды поднимаются в реестр до отрисовки
форм. Запись файлов в `definitions/` (dev-плагин) — бонус dev-режима, чтобы символ
попал в кодовую базу под git.

## Инспектор

При выделении ячейки в правой панели:

- **Символ** — название символа (у провода заголовок «Элемент», значение «Провод»,
  плюс **толщина** (степпер 0.5–20), **цвет** линии и **наконечники** на концах —
  round-trip через `data-tms-meta`). Те же поля работают на **несколько выделенных
  проводов** сразу, а последняя правка запоминается как вид следующего нарисованного
  провода (переживает перезагрузку). Крестик у цвета и толщины возвращает значение по
  умолчанию (чёрный, 2 px)
- **Наконечники провода** — по свитчу на каждый конец («нет / линиями / треугольником»,
  выбор одним кликом по миниатюре). Стрелка смотрит В точку соединения, размер
  пропорционален толщине линии; концы независимы (бывает один, бывают оба). `open` —
  две линии под 45°, `solid` — залитый треугольник (заливка идёт по диапазонам вместе
  с линией). Хранятся в `tms.arrowStart`/`arrowEnd`
- **Замок** — кнопка в правом-верхнем углу шапки инспектора: блокирует ячейку
  (или цельную группу) — read-only на холсте (нет перемещения, удаления, правки
  свойств) до снятия. Ни рамка, ни `Ctrl+A` заблокированную ячейку в выделение не
  берут — на подложку и рамку схемы замок ставят как раз затем, чтобы они не
  подхватывались массовыми операциями. Индикатор — бейдж-замок в углу ячейки. На несколько
  выделенных символов замок ставится через контекст-меню («Заблокировать (N)»:
  пока в выделении есть хоть один свободный — блокирует всех); overlay-кнопка
  остаётся у одиночного, она якорится по его габариту.
- **Навигация** — свич + поле цели hyperlink при клике в рантайме: выбор формы
  проекта из выпадашки ИЛИ **ручной ввод view-id** (для ещё не загруженной/внешней
  view). Цель вне загруженных форм — нейтральная пометка, не ошибка.
- **Значение тега** — блок появляется у символа, чья подпись помечена «показывает
  значение тега» (карточка значения и любой символ, нарисованный так же). Поля: тег
  значения, **знаков после запятой** (уезжает в `output.decimals` карточки,
  форматирует рантайм; пусто = дефолтные два знака) и **правимые подписи** символа
  (`params`) — у карточки значения это величина и единица. Пустое поле подписи
  возвращает текст из символа. У символа с подписями, но без тега значения, тот же
  блок называется «Подписи».
- Подпись как символ (`cell_text`) больше не создаётся — надписи ставятся
  инструментом разметки, а подписи прошлых форм конвертируются при открытии.
- **Анимации** — оба блока видны всегда (без кнопок «добавить»), пустой блок =
  тег не выбран; данные пишутся лениво при выборе тега/диапазона, очищаются через ×:
  - **Диапазоны значений** — тег значения, range-биндинг. Строк сколько нужно
    («Добавить диапазон» / × на строке), цвет каждой — пикером (три прежних цвета
    остались быстрыми свотчами). Границы включаются в диапазон, поэтому одинаковые
    («3 – 3») задают точное значение — так настраиваются целочисленные теги. Класс
    перекраса генерируется из цвета (), CSS-правила пишутся по
    фактически выбранным цветам. Picker тега без фильтра по типу.
  - **Булево значение** — у булевых символов
    (`hasBoolSlot`: cell_qw / cell_qr / cell_qk / cell_qf / cell_alr) первой строкой
    свой тег `slot.onoff` («Тег — для анимации самого элемента»), ниже —
    «Зависимость от других элементов» ГРУППАМИ: внутри группы теги через И, группы
    между собой через ИЛИ («+ группа» / «+ тег (И)»). Активен = выполнена любая
    группа целиком; экспорт в `shape` (одна группа) либо `multi`-карточку (≥2 групп).
    Picker — только bool-теги.
  - **Состояние по значению** — у символа с анимацией «по значению» (слот `value`):
    одна строка привязки тега-сигнала; состояния и их вид уже запечены в символе.

  Чип тега помечается амбер-иконкой, если тег **не найден в загруженном tag-list**:
  привязка к исчезнувшему сигналу иначе выглядит рабочей. Это предупреждение, не
  ошибка: tag-list мог просто устареть.

  У блоков «Булево значение» и «Диапазоны значений» в шапке — кнопки **копировать**
  (когда есть что копировать) и **вставить** (когда буфер соответствующего типа
  непуст). Копируется целиком, вместе с тегом (`useAnimationClipboard`, буфер на
  сессию, переживает смену выделения/формы); вставка идёт на всё текущее выделение
  (одиночное и мульти), пропуская несовместимые цели (`static`; свой булев тег
  `onoff` — только символам с булевым слотом).

В multi-select те же блоки работают как «применить ко всем»: булев тег раздаётся
новой группой каждому выделенному; «Диапазоны значений» — это шаблон (тег +
пороги), любая правка раздаётся на всё выделение. Символы с `static: true`
(прошлая подпись) и фигуры-разметка пропускаются. Плюс секция **«Выравнивание»** (при ≥2
ячейках) тремя подписанными категориями: **по горизонтали** и **по вертикали**
(края/центры относительно рамки выделения) + **распределение** (равные интервалы
по гор./верт., при ≥3 ячейках). Кнопки 32×32. Наложений не создаёт: ячейки,
пересекающиеся по перпендикуляру, пакуются вплотную (сводятся до касания);
центры/интервалы снапятся к сетке. Габариты берутся с учётом поворота ячейки.

## Разметка на холсте (фигуры)

Кроме символов из палитры на схему можно **рисовать разметку**: инструменты в
тулбаре холста (линия, прямоугольник, эллипс, ломаная, подпись) — те же жесты, что
в редакторе символов. Прямоугольник, эллипс и линия тянутся drag'ом (`Shift` даёт
ровный круг), ломаная набирается кликами и замыкается кликом по стартовой вершине
(двойной клик оставляет её открытой), подпись ставится одним кликом. Пока инструмент
активен, курсор — перекрестие, а рамка выделения не тянется; `Esc` возвращает к
выбору.

Фигура — не символ: **в палитре и в библиотеке проекта от рисования ничего не
появляется**, сколько бы фигур ни нарисовали. Ни портов, ни тегов, ни анимаций у неё
нет — это разметка, и в `view.svg` она уезжает статичной геометрией.

- **Текст подписи** — поле в инспекторе, **многострочное**: `Enter` добавляет строку,
  шаг истории пишется по выходу из поля. Строки выравниваются по якорю подписи, блок
  растёт вниз — точка привязки первой строки остаётся на месте, поэтому дописанная
  строка не сдвигает уже расставленную подпись. Автоматического переноса по ширине
  нет: где перенос — решает автор. Пустое поле удаляет подпись: без текста её не
  видно и не выделить.
- **Вид** правится в инспекторе: цвет и толщина линии, у замкнутых фигур —
  **заливка** (галка «есть/нет» + свотч цвета); у подписи — текст, размер, шрифт,
  жирность, цвет и выравнивание (якорь роста, как у `cell_text`). Новая подпись
  создаётся выровненной **по левому краю** — клик ставит начало текста. Скругления у
  разметки нет.
- **Размер** — ручки у выделенной фигуры: тянут габарит, геометрия масштабируется под
  него. У линии и ломаной вместо габаритных ручек точки на вершинах (рамка вокруг
  наклонной линии ничего не задаёт) — правятся как в редакторе символов.
- **Поворот** доступен подписи (у остальных фигур ручки тянут габарит в экранных
  осях). Отражение — только у символов.
- Всё остальное работает как у символов: перемещение, копипаст и дубль, слои
  (`Ctrl+[` — увести подложку назад), группы, замок, удаление, undo.

## Группировка

Выделенные (≥2) элементы можно **объединить в группу** — `Ctrl+G` (разгруппировать
`Ctrl+Shift+G`), пункт контекст-меню или кнопка в инспекторе. Группа ведёт себя как
единый объект: клик по любому члену выделяет всю группу, перетаскивание двигает её
целиком, инспектор показывает её как один элемент (общий замок + анимации на всех).
При наведении на члена группа обводится пунктирной рамкой; в hover-плашке — «В группе
(N)». Копия группы (copy/paste, дубль) получает свою новую метку. Модель — логическая
(`tms.groupId` на членах, round-trip через `data-tms-meta`), без вложенности.

## Холст: навигация

Колесо мыши **прокручивает** холст по вертикали, **Shift + колесо** — по горизонтали,
**Ctrl/Cmd + колесо** — зум к позиции курсора (как в Figma, Visio, draw.io). На
трекпаде двухпальцевый жест прокручивает, pinch — масштабирует. Панорамирование
мышью — средняя кнопка или Space + ЛКМ; кнопка «Вписать» в тулбаре подгоняет масштаб
под содержимое (не крупнее 100%).

## Холст: копирование и вставка

`Ctrl+C` / `Ctrl+V` копируют выделенные символы со всеми свойствами (теги, стиль,
поворот, отражение, масштаб) и провода, целиком принадлежащие выделению: каждый конец
либо на выделенном символе, либо свободен (тогда его точка сдвигается вместе с
копиями). Провод, у которого свободны **оба** конца, к набору символов не относится и
не копируется.
Каждая вставка встаёт со сдвигом от **предыдущей копии в её текущем месте**: отвезли
копию в сторону, нажали `Ctrl+V` снова — новая появится рядом с той, что отвезли, а не
рядом с оригиналом. Если копии удалили или сменили форму, отсчёт снова идёт от
оригинала. `Ctrl+D` дублирует выделение на месте — каждый следующий дубль отступает от
предыдущего.

Копия не наследует закрепление на шине: она встаёт со сдвигом, то есть уже не на шине —
перетащите её туда сами. Одиночный член группы при вставке разгруппировывается (группа
из одного бессмысленна), группа целиком получает новую метку.

## Поиск (Ctrl+F)

Плавающий виджет ищет по: всем `slots.*`, `rangeSource.tag`,
`boolSource` (все теги групп), `navigation`, правимым подписям символа (`params`),
а также по тексту надписи — и подписи-разметки, и `cell_text`
(на схеме это одна и та же надпись, разница в типе ячейки автора не касается). Совпадения
подсвечиваются амбер-ореолом, текущее — насыщенный оранжевый, паном
центрируется в viewport (если за пределами). Enter/F3 — следующее,
Shift+Enter/F3 — предыдущее, Esc — закрыть.

## Холст: фон формы

Клик по кнопке-палитре в тулбаре открывает нативный пикер сразу; выбранный цвет
закрепляется за **активной формой** — открыл другую, холст перекрасился в её цвет, у
остальных остаётся дефолтный. Пока диалог открыт, холст перекрашивается живьём, а в
проект цвет пишется один раз по закрытию. Если у формы задан свой фон, на иконке
появляется крестик — он и сбрасывает к дефолту, и служит признаком «фон здесь не
дефолтный». Точки сетки подбираются под яркость фона сами, отдельной настройки нет.

Это **свойство проекта**, а не браузера: фон живёт в мете (`formBg`), переживает reload,
уезжает в архив файлом `project.json` и возвращается при импорте — у коллеги проект
откроется в тех же цветах. В `view.svg` фон не попадает: в рантайме его даёт панель
WebScada. Контуры символов остаются чёрными, поэтому тёмный фон меняет вид только в IDE.

## Холст: аффордансы (порты, ручки, кнопки)

Вокруг выделенного элемента живут разные интерактивные точки, и роль каждой читается
по форме и цвету — иначе они сливаются в кашу:

| Роль                                    | Вид                                                          |
| --------------------------------------- | ------------------------------------------------------------ |
| порт (тянуть провод)                    | белый кружок, **чёрная** обводка; виден только при наведении |
| ручка провода (концы и изломы)          | белый кружок, **амбер** обводка                              |
| ручка масштаба / габарита / точки линии | круг, залитый **primary**, белая рамка; центр ровно на углу  |

Ручки масштаба стоят в экранных пикселях (не растут с зумом), порты — в модельных
(растут вместе со схемой): порт это часть схемы, ручка — инструмент.

## Холст: порты по ховеру

Порты ячеек по умолчанию скрыты и проявляются **при наведении** — наводишь на
элемент, видишь куда тянуть провод. У выделенного их нет: там по углам габарита стоят
ручки масштаба, и вместе с портами символ превращался в кашу аффордансов. Рисование
провода это не задевает — курсор всё равно над символом, значит порты видны. Чистый
CSS (`.joint-element:hover`), без JS; заливка порта белая, обводка чёрная — cyan-круги
заняты ручками, и в одинаковых цветах роли сливались.

## Холст: поворот и отражение

Выделенное можно **повернуть** (overlay-кнопки ↺/↻ или `R` / `Shift+R`, шаг 90°) и
**отразить** по горизонтали/вертикали (overlay-кнопки flip или `Shift+H` / `Shift+V`).

**У символа** отражение зеркалит и картинку, и позиции портов — подключённые провода
следуют за ними; работает поверх поворота (кнопка задаёт экранную ось независимо от
угла). Хранится в `tms.flipH`/`flipV`, переживает round-trip. Недоступно для
`noRotate`-символов (text/bus/pi) и заблокированных.

**У фигуры-разметки** преобразуется САМА геометрия (тем же `rotateShape90` /
`flipShape`, что в редакторе символов), а не вешается трансформ: габарит остаётся в
модельных осях, поэтому ручки ресайза продолжают тянуть края как обычно, а в `view.svg`
уезжает уже готовая геометрия — новых полей в round-trip не появляется. Кнопка видна
только когда операция меняет картинку: круг и квадрат не поворачиваются, прямоугольник
и ортогональная линия не отражаются. Подпись — исключение: её глифы горизонтальны,
поэтому её вращает `angle` ячейки, а отражения у неё нет вовсе — зеркальный текст не
нужен, а якорь роста задаётся полем «Выравнивание» в инспекторе.

## Холст: порядок наложения (слои)

Порядком управляет контекст-меню → **«Порядок»** или `Ctrl+]` / `Ctrl+[` (с `Shift` —
на передний / задний план); команда применяется ко всему выделению.

Символы и провода — **разные слои** со своими полосами `z` (символы от 0 вверх,
провода в минусах), поэтому «на задний план» не роняет символ под провода, а
поднятый провод не всплывает над ними. У **разметки** есть третий слой — подложка
ниже проводов: залитая плашка на дне слоя символов всё равно закрывала их. Отдельной
кнопки нет, туда водят те же команды: «на задний план» кладёт фигуру под провода
сразу, «ниже» — когда она уже на дне слоя символов, «выше» и «на передний план»
возвращают обратно. Символы и провода в подложку не попадают. У проводов порядок виден на пересечении:
мостик (`jumpover`) рисует тот, что выше, — так выбирается, какой провод идёт
поверх. Порядок переживает round-trip (`meta.z`).

## Холст: врезка и срастание проводов

**Врезка** — drop символа с **≥2 портами** из палитры на провод разбивает его
на два сегмента с проходом через элемент: исходный линк переиспользуется как
`source→cell.in`, добавляется `cell.out→target` с клоном анимаций; элемент
наследует диапазоны/булево провода (но его собственная конфигурация приоритетнее —
наследуется только то, чего у него нет). Во время drag над проводом превью липнет
к линии и поворачивается под угол врезки.

- Угол врезки (`utils/wireSplice.js` → `spliceRotation`): пара проходных портов
  выравнивается вдоль **локального сегмента** провода в точке врезки (касательная
  `wireDirAt`, не линия центров — rightAngle-роутер гнёт провод). Для 2-портовых
  из двух вариантов (±180°) сторона курсора выбирает разворот: на горизонтальном
  сегменте курсор выше → по часовой, ниже → против; на вертикальном слева → как
  есть, справа → 180°.
- Выбор пары портов (`pickPassThroughPorts`) — тоже вдоль локального сегмента.
- Ручные изломы провода распределяются по сегментам относительно точки врезки
  (по длине вдоль пути): что было до неё — остаётся на первом сегменте, что после
  — переезжает на второй.

Вся геометрия/топология врезки и превью живёт в `composables/useWireSplice.js`
(чистые функции — в `utils/wireSplice.js`).

**Срастание** — удаление **одного** элемента, через который проходят ровно
**2 провода к 2 разным соседям**, объединяет их в один (вместо разрыва): выживший
линк перецеливается на дальний конец второго ещё до удаления (иначе каскад
JointJS снёс бы оба). Логика — `utils/wireSplice.js` → `planWireBridge`;
применяется в `useCanvas.deleteItems` (через него идут все пути удаления: Del,
контекстное меню, оверлей-кнопка, инспектор). Изломы обоих проводов сшиваются в
один список (с учётом порядка и реверса). В multi-select срастание НЕ делаем —
туда авто-попадают мостовые провода между ячейками, сохранять нечего.

## Холст: конец провода на холсте

Провод не обязан заканчиваться на символе: отпустил конец на пустом месте — провод
остаётся, а конец **помечается точкой**. Отдельного символа «Точка соединения» для
этого больше нет — точка стала частью провода и наследует его цвет, толщину и
анимации (диапазон, обесточивание красят её вместе с линией). Диаметр считается от
толщины провода, как раствор наконечника.

Точка выводится из привязки конца, а не хранится полем: привязали конец к порту —
точка ушла, отцепили — вернулась. Отдельного контрола в инспекторе у неё нет, а
выбранный наконечник (стрелка полая или заполненная) её вытесняет: наконечник —
решение автора, точка лишь метка «здесь провод кончается». Перецепить конец можно
ручкой у выделенного провода.

Провод со свободным концом едет вместе с выделением: `Ctrl+A`, рамка или
перетаскивание группы двигают такие концы наравне с символами (иначе линия
растягивалась бы, а точка оставалась на месте).

Схемы прошлых версий переезжают сами: `cell_node` с одним проводом или без проводов
растворяется на загрузке (конец провода встаёт свободной точкой в центр бывшего
узла), узел с двумя и более проводами остаётся символом — о них сообщает
предупреждение импорта. Сам символ из палитры убран.

## Холст: ручные изломы провода

У выделенного провода доступен тул `linkTools.Vertices`: drag по линии создаёт
излом, drag по излому двигает маршрут, double-click добавляет точку,
`redundancyRemoval` убирает излом, легший на прямую между соседями. Изломы
снапятся к сетке (`change:vertices`-хендлер) — край не отрывается от линии,
которую держит на сетке `gridRightAngleRouter` (snap-обёртка над `rightAngle`).
Роутеру нужен `useVertices: true`, иначе `rightAngle` игнорирует изломы.
Эндпоинт-ручки реконнекта рендерятся **поверх** vertex-adding обёртки (порядок
тулов), иначе клик у конца провода добавлял бы излом вместо перемещения. Изломы
переживают round-trip через `data-tms-meta`.

## Холст: подключение к шине

Слоты шины стоят **в середине толщины** — один ряд `p_i` с шагом `BUS_PORT_SPACING`
(20). Слот шины физически одна точка цепи, поэтому провод приходит в него с любой
стороны: сторону подхода роутер берёт по геометрии (`insideApproachDirection` в
`linkDefaults`), а не по ближайшей стороне габарита — иначе все провода заходили бы
сверху. Вход к шине всегда перпендикулярен телу: с торца провод шёл бы вдоль неё.

Занятый слот получает **маркер соединения** — контрастную точку в цвете провода
(`collectBusMarks` + `buildBusExportSvg`). Он нужен и на холсте, и в `view.svg`: порт
лежит под телом шины, и без точки «соединено» не отличить от «провод проходит мимо»
(в экспорте портов нет вовсе, на холсте они скрыты до hover).

## Холст: символ на шине

Символ, перенесённый на шину (drop из палитры или drag уже стоящего), ложится на неё
**центром** — поперёк на линию шины, вдоль по снапу к сетке — и **закрепляется**
(`tms.busId`, см. `useBusSnap`). Двигаешь шину или меняешь ей толщину — закреплённые
едут за ней. Проводов при этом не появляется: символ на шине не соединяется, он на ней
лежит; z поднимается выше шины, если символ был под ней.

Подносишь снизу — символ в исходной ориентации, сверху — развёрнут на 180°
(`noRotate` и `noFlip`-символы — карточка значения, подпись — не разворачиваются:
перевёрнутая надпись не читается). Увёл символ мышью с шины — закрепление
снимается само; «Снять с шины» в контекст-меню открепляет, не сдвигая символ.
Закрепление переживает round-trip (`busId` в `CELL_META_FIELDS`); ссылка на
отсутствующую в архиве шину снимается на импорте с сообщением.

## Холст: вид шины и точки соединения

Тело шины и точку соединения можно красить (свотч) и менять им толщину — у шины это
её высота, у точки диаметр. Минимум — дефолтный вид: тоньше тело сливается с
проводами. Цвет **базовый**: привязанные диапазоны и обесточивание заливают его
поверх, поэтому свой цвет виден, пока рантайм не включил ни один animation-класс.

## Холст: размер символа

Символ масштабируется **пропорционально** за угловые ручки выделения: множитель
хранится в `tms.scale` (×1…×4), размер экземпляра из него выводится. Сам `shape.svg`
не перерисовывается — рисунок растягивается трансформом, тем же на холсте и в
`view.svg`; обводка растёт вместе с символом.

Габарит и порты садятся на сетку: обе стороны снапятся к шагу 5, крайние порты липнут
к границам символа (иначе вывод уехал бы внутрь тела, и провод подключался бы «в
символ»), внутренние округляются к клетке. Поэтому концы проводов остаются на сетке, а
маршруты — ортогональными. Ниже родного размера не уменьшаем: порты сошлись бы в одну
клетку и два провода стали бы неразличимы.

Карточка значения (`cell_value`) масштабируется тем же жестом — своей ширины у неё
нет, текст растёт вместе с карточкой. Следствие: длинное значение не «впишешь»
растягиванием при том же кегле, растёт вся карточка.

Не масштабируются те, у кого габарит свой: шина (ресайз за края), прошлая подпись
`cell_text` (размер от текста), точка соединения (диаметр полем `tms.dotSize`).
Заблокированные ручек не получают, а вот поворот масштабу не мешает: ручки едут на
визуальные углы, вектор жеста поворачивается на −angle, а позиция считается от
визуального якоря — иначе символ уползал бы из-под курсора (поворот идёт вокруг центра,
а центр при смене размера уезжает). Масштаб переживает round-trip, копию
(paste) и правку самого символа — экземпляр остаётся ×2, даже если символ в редакторе
изменил размер.

## Холст: ресайз шины

Шина (`cell_bus`) тянется за edge-хэндлы. Резайз через нативный
`cell.resize(w, h, { direction })` (`useBusResize`): `direction:'right'` держит
левый край, `'left'` — правый. Ширина снапится к `BUS_PORT_SPACING` (20) — один
шаг = один слот порта. При резайзе **влево** origin уезжает, поэтому порт-рефы
подключённых линков сдвигаются на число слотов (`p_i → p_(i+k)`) — порты не
пересоздаются, абсолютные позиции подключённых проводов сохраняются.

**Сжатие** прижимает провода к крайнему существующему слоту (с обеих сторон
одинаково): исчезнувший слот означает несуществующий порт, а провод на нём после
перезагрузки уехал бы в центр шины. Ничего не удаляется, отмена — `Ctrl+Z` вместе
с ресайзом.

## Экспорт

`exportProject(graph)` собирает:

- **view.svg** — целостный SVG с inline `<style>` для animation-классов.
  На каждой ячейке `id="animation-{stencilId}-{animId}"` + `data-tms-meta`
  (JSON для round-trip'а) — схема одна на все символы, включая карточку значения.
  Провода — `<path id="animation-wire-{shortLinkId}">`;
  провод с наконечниками уезжает группой `<g id="animation-wire-…">` (линия + `<path>`
  стрелок), чтобы CSS-анимации доставали и до наконечника.
- **animations.json** — мапа `id → card` для WebScada-рантайма.

cellId/linkId = JointJS UUID, стабилен между сессиями. Если у ячейки есть
`navigation`, animation-entry получает поле `"navigation": "view_id"` —
рантайм откроет указанную view при клике.

CSS в SVG:

- `*:not(text)` для `stroke` — текст не перекрашивается
- opt-in классы заливки: `.tms-range-fill` (диапазоны/off: тело шины, точка
  соединения, залитый наконечник) и `.tms-state-fill`
  (цвет состояния, замкнутые фигуры stateful-символов)
- `.animation-off` (slate-500) — поверх классов диапазонов
- `.animation-hidden { display: none }`
- `[data-tms-stencil="..."].animation-off .animation-hidden { display: initial }`
  — генерится для каждого символа с `quality: true` (cell_qk / cell_qr /
  cell_qf). При bad-качестве показываем обе позиции рычага одновременно:
  «данные ненадёжны, не врём про конкретное состояние»

### Quality-биндинги

Для символов с флагом `quality: true` в stencil.json (cell_qk / cell_qr /
cell_qf) exporter автоматически генерирует биндинг по каждому привязанному
тегу с `source: 'quality'` и кейсом `[0, 191] → addClass: animation-off`.
Рантайм при bad/uncertain quality (< 192) красит ячейку серым; CSS-override
выше показывает обе позиции рычага.

## Round-trip

`view.svg` каждой формы открывается обратно — `projectLoader` читает
`data-tms-meta` и восстанавливает JointJS-граф. Один файл для рантайма и для
редактирования.

Провод с отцепленным концом тоже переживает выгрузку: свободный конец пишется точкой,
а при чтении привязка возвращается, если точка совпала с портом символа — иначе конец
остаётся свободным, и об этом сообщает предупреждение.

Архив приходит извне, поэтому значения из `data-tms-meta` нормализуются на обоих концах
(и при чтении, и при записи): число знаков после запятой, размер шрифта, толщина линии
клампятся диапазоном, выравнивание и шрифт проходят whitelist, границы диапазонов
приводятся к числам, угол — к 0..359. Фигура чужого `shape.svg` без обязательных
размеров отбрасывается, иначе в файл символа уехало бы `width="NaN"`. Полнота
round-trip'а закреплена тестом: каждое поле контракта обязано вернуться после
экспорта и разбора.

## Портативная сборка (десктоп)

IDE собирается в самодостаточный файл — Electron несёт свой Chromium, поэтому на
машине пользователя не нужны ни Node, ни браузер, ни установка:

| ОС      | Артефакт                                       | Запуск                                                                                                     |
| ------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Windows | `tms-ide-<version>-win.exe` (portable, ~90 МБ) | двойной клик; при первом запуске SmartScreen → «Подробнее» → «Выполнить в любом случае» (файл не подписан) |
| Linux   | `tms-ide-<version>-linux.AppImage`             | `chmod +x` и двойной клик                                                                                  |

Артефакты кладутся в `../release-tms/` — вне дерева проекта: внутри рабочей папки
Windows отдаёт EPERM при распаковке (файлы держит вотчер IDE или антивирус).
Раздавать нужно **только сам исполняемый файл**: `win-unpacked/` и остальное рядом
— промежуточные результаты упаковщика.

Внутри окна работает та же IDE, что в браузере, без урезаний: автосохранение,
импорт/экспорт `.zip`, редактор символов. Отличия десктопа:

- Меню приложения нет — его акселераторы перехватывали бы `Ctrl+C/V/A/F`,
  занятые холстом. `F12` открывает DevTools.
- Окно никуда не уходит со своей страницы: внешняя ссылка открывается в системном
  браузере (и только `http`/`https`/`mailto`), а рендерер работает под CSP —
  внешних загрузок из окна не бывает. `desktop:smoke` заодно проверяет, что политика
  ничего не заблокировала.
- При закрытии окна с правками, не попавшими в `.zip`, спрашивается подтверждение.
- Данные проекта живут в профиле приложения (`%APPDATA%\tms-ide-vue` на Windows),
  а не рядом с файлом. Перенос на другую машину — выгрузить `.zip` и открыть его
  на новом месте.

Иконка берётся из `public/favicon.svg`: `npm run icon:build` рендерит её в
`build/icon.png` 512×512, из которого упаковщик делает `.ico`.

## Проект (формы + библиотека)

IDE работает с **проектом** — набором форм (схем) + библиотекой символов.
Открыта одна форма; формы — дерево (навигатор в левой панели над палитрой; клик
по узлу → форма на холсте). Иерархию узлов (из `hierarchy.json`) можно
перестраивать перетаскиванием; она — метаданные редактора (на экспорт SVG и
рантайм не влияет). Состояние проекта (формы пер-id, активная, теги, дерево)
хранится в IndexedDB и переживает перезагрузку. Имя проекта = имя открытого
`.zip` (без расширения) — показывается в топ-баре у логотипа и используется как
имя файла при экспорте. Статус справа в топ-баре показывает единственное
состояние — «не сохранено» (браузер не смог записать в IndexedDB, риск потери
работы); в норме полоса пуста. Успешный автосейв молчит — кричим только про ошибку записи.

Если хранилище **не прочиталось** при старте (браузер отказал в доступе, битая
транзакция), приложение не считает это «пустым проектом»: автосохранение
выключается целиком, показывается ошибка с просьбой перезагрузить страницу, а
данные в IndexedDB остаются нетронутыми — иначе пустой холст затёр бы проект.

- **Формы** — дерево в левой панели: «+» в шапке создаёт пустую (падает
  последним узлом в корень), кнопка-копия дублирует форму (`<id>_copy`, копия
  встаёт сиблингом и открывается), карандаш у строки — переименование, × —
  удаление (единственную удалить нельзя), **drag-and-drop** переносит/вкладывает узлы
  (линия между строками = переставить, подсветка узла = вложить внутрь; своё
  поддерево — недоступная цель). Формы вне дерева показываются группой «Без
  иерархии», узлы на несуществующую форму — битыми. Имя формы = имя папки при
  экспорте = цель навигации, поэтому переименование заодно чинит ссылки
  `tms.navigation` на старое имя во всех формах.
- **Открыть проект** (`Ctrl+O`) — выбрать **.zip**-архив проекта (файловый picker:
  File System Access, а где его нет — обычный `<input type="file">`, см. «Браузеры»).
  Раскладка внутри: `forms/<id>/view.svg` → формы,
  `library/<id>/{stencil.json,shape.svg}` → символы, `taglist.csv` → теги,
  `hierarchy.json` → дерево форм. Подписи прошлого формата (символ `cell_text`)
  конвертируются в примитив текст на входе — и при открытии `.zip`, и при
  восстановлении форм из IndexedDB, так что формат не живёт в двух вариантах.
  Символы из бандла регистрируются в рантайме сразу
  (форма рисуется без ожидания reload): новые (нет в реестре) и **изменённые** —
  чья версия в бандле отличается от реестра (правка заливки/анимации), иначе
  правка «слетала» бы на встроенную версию. Их оверрайды пишутся в IndexedDB
  (переживают reload в проде); файлы в `definitions/` дописываются dev-плагином
  (бонус dev-режима). Символы, которых нет ни в базе, ни в бандле,
  попадают в предупреждение. Символ с id вне маски `[a-z0-9_]` не регистрируется
  и не пишется в хранилище (id уезжает в атрибут и CSS-селектор экспортного SVG) —
  такие символы перечисляются отдельным предупреждением, молча они не исчезают. Пустые формы (заготовки, цели навигации) сохраняются
  — отбрасывается только битый SVG. Если запись в IndexedDB не прошла целиком
  (квота), импорт сообщает об этом и не перезагружает страницу.

  **Имена форм чинятся на входе.** Имя формы — это имя папки в архиве и адрес view в
  рантайме, поэтому недопустимые символы заменяются (`Form 3` → `Form_3`), а имя,
  которое чинить бессмысленно (кириллица, путь наружу вроде `..`), получает `form_N`.
  Форму не теряем — переименовываем и говорим об этом тостом; вместе с именем
  переезжают ссылки `tms.navigation`, иерархия и фон формы. Битый `hierarchy.json`
  импорту не мешает: проект открывается плоским списком форм.

- **Экспортировать проект** (`Ctrl+S`) — скачивание одного **.zip** (той же
  раскладки, имя файла = имя проекта): по форме `view.svg`+`animations.json`, используемые символы в
  `library/`, `taglist.csv`, дерево форм `hierarchy.json`. Геометрия проводов
  снимается с реально отрисованного paper (формы прогоняются через холст под
  оверлеем).
- **Символы — физические файлы** в `src/stencils/definitions/` (Vite-glob).
  Персистентный реестр — статичный glob; браузер сам в исходники писать не может,
  поэтому запись/удаление идут через dev-плагин (`vite.config.js`): импорт проекта
  и редактор символов шлют `POST /__stencils/import`, удаление из палитры —
  `POST /__stencils/delete`. `registerStencil` / `unregisterStencil` держат реестр
  в актуальном виде до reload (реактивно через `registryVersion` — палитра
  обновляется без перезагрузки). Персистентность правок вне dev держит
  `stencilOverrides` (IndexedDB): импорт/редактор пишут туда изменённые и новые
  символы, старт поднимает их в реестр. Сравнение «изменился ли» — по
  `stencilSignature` (устойчиво к порядку полей); неизменённые встроенные не
  дублируются.
