# TMS IDE (Vue)

Web IDE на Vue 3 для сборки SVG-мнемосхем SCADA и экспорта пары
`view.svg` + `animations.json` для WebScada-рантайма.

## Стек

- **Vue 3.5** (Composition API, `<script setup>`)
- **Pinia 4** — state management
- **Vite 8** (Rolldown) — build / dev
- **PrimeVue 4** (Aura, primary cyan) — UI kit
- **Tailwind CSS 4** (CSS-first, плагин `@tailwindcss/vite` — конфиг-файлов нет) — layout / utility
- **@joint/core 4** (JointJS) — SVG-редактор
- **fflate** — ZIP-экспорт/импорт проекта архивом
- **interactjs** — drag/resize/снап примитивов в редакторе стенсилов
- **@vueuse/core** — listener'ы/observer'ы с auto-cleanup
- **Vitest 4 + jsdom + @vue/test-utils 2** — unit- и компонентные тесты

## Запуск

Нужна **Node 22.22+ / 24.15+** (планку задаёт jsdom 30 в тестах; проверяется через
`engines` в package.json).

```bash
npm install
npm run dev       # http://localhost:5174/
npm run build     # production-сборка в dist/
npm test          # тесты однократно
npm run lint      # eslint
npm run format:check  # prettier
npm run knip      # неиспользуемые экспорты
```

CI (GitHub Pages, `.github/workflows/deploy.yml`) на каждый push в `main` гоняет
`format:check` → `lint` → `test` → `knip` → `build`, поэтому любой из этих шагов
валит деплой.

## Модель стенсила

> В интерфейсе сущность называется **«символ»** (палитра, инспектор, редактор); в
> коде и формате проекта — `stencil` (`stencilId`, `definitions/`, `library/`).

Каждый стенсил — папка в `src/stencils/definitions/<id>/`:

- `stencil.json` — id, label, category, size, ports + опционально slots,
  animationTemplate, `states` (анимация «по значению»), `stateColors` (цвет
  символа по состоянию: строка = контур или `{stroke, fill}`), minWidth (только cell_bus)
- `shape.svg` — SVG c атрибутами `data-anim-suffix` на анимируемых элементах

Реестр строится автоматически (Vite glob), перезапуск не нужен.

### Слоты

```json
{
  "key": "onoff",
  "type": "Boolean"
}
```

Только `key` обязателен; `type` опционален. В `animationTemplate.bindings.tag` —
placeholder `{slot.KEY}`. При экспорте подставится выбранный тег. Слот без
значения → биндинг отбрасывается.

Picker слота фильтрует теги по `type`: булевы слоты (`type: Boolean`) — только
bool-теги из tag-list (по типу, не по суффиксу имени). Слот `value` (анимация «по
значению») — без фильтра (сигнал может быть кодом/enum).

### Декларативные флаги в stencil.json

Спец-поведение стенсила объявляется прямо в его JSON — exporter / Inspector /
Canvas читают флаги, никаких хардкод-списков в коде:

| Поле                | Значение                                                                                | Где применяется                             |
| ------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------- |
| `quality: true`     | эмитит range-биндинг `[0,191] → animation-off` на outer                                 | cell_qr / cell_qk / cell_qf                 |
| `static: true`      | без visual-реакции на animation-классы; multi-select пропускает; detailTags не собирает | cell_text / cell_value                      |
| `noRotate: true`    | оверлей-кнопки rotate не рендерятся                                                     | cell_text / cell_value / cell_bus / cell_pi |
| `defaults: { ... }` | merge в `tms` при создании ячейки                                                       | cell_text (`text`), cell_value (`valueTag`) |
| `valuePresets: []`  | справочник величин «подпись + единица» (+ опц. `suffix` для автоподстановки)            | cell_value                                  |

«Булев стенсил» (свой тег рендерится первой строкой BooleanBlock) выводится
по convention: стенсил со слотом `key === 'onoff'`. Helper `hasBoolSlot`.

### Редактор стенсилов (создание и правка в IDE)

Кнопка «+» в шапке палитры открывает редактор-оверлей поверх холста; пока он
открыт, боковые панели `inert` (без кликов/фокуса).
Рисование примитивов (line / rect / circle / polyline / подпись; ломаная замыкается кликом
по стартовой вершине → `polygon`) + расстановка портов **на границе** стенсила, всё
со снапом к сетке (вершины фигур — 1px, порты и размер — шаг 5); правка /
перемещение / ресайз — через interactjs (колбэки пишут в модель, Vue
перерисовывает). Undo/redo (Ctrl+Z / Ctrl+Y) откатывает и фигуры с портами, и
метаданные символа (подпись, размер холста, режим анимации, состояния, их цвета);
копирование выделенной фигуры со всеми свойствами — Ctrl+C / Ctrl+V. Холст обрамлён
линейками X/Y (деления 10/5/1). Выделение показывается halo-обводкой под фигурой
(реальные цвета видны поверх) + ручки. На сохранении контент обрезается до bbox
(кратно шагу сетки) и сдвигается в (0,0) — «воздух» холста отбрасывается. **Размер холста**
(Ш×В) правится в тулбаре рядом с инструментами. Правая панель `StencilInspector` —
две плашки: «Стенсил» (id `[a-z0-9_]` / label / категория, флаг `noRotate`, анимация
состояния) и «Фигура» (цвет линии / толщина / заливка / скругление + видимость
выделенной фигуры). Валидация — при сохранении. **Анимация состояния** (единый свитч «Выкл / Булево / По значению», один режим за раз):
у выделенной фигуры задаётся видимость по состоянию; на выходе — слот-драйвер +
карточки `animationTemplate`, прячущие группу `animation-hidden` на «чужих» значениях.

- **Булево** — 2 состояния (`.true`/`.false`), слот `onoff`.
- **По значению** — N состояний (`meta.states = { key, label, code }`), слот `value`,
  суффикс группы = стабильный `key`, код (значение сигнала) вписывает автор. Пресет
  подписей + шаблон «Сигнал положения» (Включен/Отключен/Промежуточное/Недостоверно) —
  для разъединителей/отделителей по СТО 56947007.

**Цвет состояния.** У каждого состояния — свотчи «Контур» и «Заливка»
(`meta.stateColors`, строка = только контур либо `{stroke, fill}`). Контур красит
`stroke` всех потомков; заливка (`fill`) — только замкнутые фигуры (rect/circle/
polygon, opt-in класс `tms-state-fill`), поэтому контур/hit-area не заливаются
«блобом», а контурную фигуру можно закрасить в конкретном состоянии (лампа). Свотч
заливки виден лишь при наличии заливаемых фигур. Пусто → состояние меняет только
видимость. На выходе — `stateColors` в stencil.json; exporter вешает класс
`animation-color-<id>-<key>` на outer, CSS перекрашивает потомков. **Обесточивание
(`animation-off`) бьёт цвет** — `:not(.animation-off)` в правиле, т.е. де-энергизация
(напряжение/quality с холста) остаётся серой поверх подсветки состояния.

Превью состояния — плавающий Select слева-сверху на холсте (эмуляция видимости +
цвета, на экспорт не влияет). Чекбокс `quality` (серость + «показать все положения»
при bad-качестве) — в том же блоке анимации, только при включённой анимации.
Де-энергизация (серость по напряжению/качеству) в стенсиле не задаётся — это холст
(`boolSource`/`rangeSource`). Стенсил регистрируется в реестре сразу (появляется
в палитре) и пишется в `definitions/<id>/` dev-плагином.

Правка — кнопка-карандаш в строке стенсила (по ховеру, у всех **кроме залоченных**
`locked: true`). Залочены те, чей SVG редактор не воспроизвёл бы без потерь:
программные без `shape.svg` (bus / text / value), с текстом (pi), с нестандартными
атрибутами обводки (alr — скругления), и структурная точка `cell_node`. Коммутация
qw / qr / qk / qf **редактируема** (единый формат `.true` / `.false`). Открывает
редактор с загруженным стенсилом (`parseStencilSvg`
разбирает `shape.svg` обратно в примитивы, порты — из `stencil.json`); id заблокирован
(= имя папки). На сохранении переинжектит активную форму — расставленные экземпляры
подхватывают новый рисунок; при смене размера/портов предупреждает (их геометрия у
экземпляров не трогается).

Удаление — кнопка-корзина в строке стенсила (по ховеру, у всех **кроме залоченных**
`locked`) с ConfirmPopup: снимает из реестра + сносит папку. Если стенсил расставлен
в формах, удаление отклоняется (не осиротить ячейки), с указанием где.
Персист: правка/новый стенсил пишется оверрайдом в IndexedDB (`stencilOverrides`)
и переживает reload и в проде; на старте оверрайды поднимаются в реестр до отрисовки
форм. Запись файлов в `definitions/` (dev-плагин) — бонус dev-режима, чтобы стенсил
попал в кодовую базу под git.

## Инспектор

При выделении ячейки в правой панели:

- **Символ** — название стенсила (у провода заголовок «Элемент», значение «Провод»,
  плюс **толщина** (степпер 0.5–20) и **цвет** линии — round-trip через `data-tms-meta`)
- **Замок** — кнопка в правом-верхнем углу шапки инспектора: блокирует ячейку
  (или цельную группу) — read-only на холсте (нет перемещения, лассо, удаления,
  правки свойств) до снятия. Индикатор — бейдж-замок в углу ячейки.
- **Навигация** — свич + поле цели hyperlink при клике в рантайме: выбор формы
  проекта из выпадашки ИЛИ **ручной ввод view-id** (для ещё не загруженной/внешней
  view). Цель вне загруженных форм — нейтральная пометка, не ошибка.
- **Значение тега** (`cell_value`) — тег значения + **величина**: пара «подпись +
  единица» из справочника символа (`valuePresets` в его `stencil.json`). Пара
  подставляется автоматически по суффиксу тега (`.UA` → «Ua · В»), выбор в списке
  её перебивает — имена тегов не во всех проектах следуют конвенции. Пары нет и не
  выбрана — подпись пустая (подпись из суффикса читалась как ошибка).
- **Анимации** — оба блока видны всегда (без кнопок «добавить»), пустой блок =
  тег не выбран; данные пишутся лениво при выборе тега/диапазона, очищаются через ×:
  - **Диапазоны значений** — аналоговый тег,
    range-биндинг, классы `animation-low/-mid/-high`. Picker без фильтра по типу.
  - **Булево значение** — у булевых стенсилов
    (`hasBoolSlot`: cell_qw / cell_qr / cell_qk / cell_qf / cell_alr) первой строкой
    свой тег `slot.onoff` («Тег — для анимации самого элемента»), ниже —
    «Зависимость от других элементов» ГРУППАМИ: внутри группы теги через И, группы
    между собой через ИЛИ («+ группа» / «+ тег (И)»). Активен = выполнена любая
    группа целиком; экспорт в `shape` (одна группа) либо `multi`-карточку (≥2 групп).
    Picker — только bool-теги.
  - **Состояние по значению** — у стенсила с анимацией «по значению» (слот `value`):
    одна строка привязки тега-сигнала; состояния и их вид уже запечены в стенсиле.

  У блоков «Булево значение» и «Диапазоны значений» в шапке — кнопки **копировать**
  (когда есть что копировать) и **вставить** (когда буфер соответствующего типа
  непуст). Копируется целиком, вместе с тегом (`useAnimationClipboard`, буфер на
  сессию, переживает смену выделения/формы); вставка идёт на всё текущее выделение
  (одиночное и мульти), пропуская несовместимые цели (`static`; свой булев тег
  `onoff` — только стенсилам с булевым слотом).

В multi-select те же блоки работают как «применить ко всем»: булев тег раздаётся
новой группой каждому выделенному; «Диапазоны значений» — это шаблон (тег +
пороги), любая правка раздаётся на всё выделение. Стенсилы с `static: true`
(cell_text / cell_value) пропускаются. Плюс секция **«Выравнивание»** (при ≥2
ячейках) тремя подписанными категориями: **по горизонтали** и **по вертикали**
(края/центры относительно рамки выделения) + **распределение** (равные интервалы
по гор./верт., при ≥3 ячейках). Кнопки 32×32. Наложений не создаёт: ячейки,
пересекающиеся по перпендикуляру, пакуются вплотную (сводятся до касания);
центры/интервалы снапятся к сетке. Габариты берутся с учётом поворота ячейки.

## Группировка

Выделенные (≥2) элементы можно **объединить в группу** — `Ctrl+G` (разгруппировать
`Ctrl+Shift+G`), пункт контекст-меню или кнопка в инспекторе. Группа ведёт себя как
единый объект: клик по любому члену выделяет всю группу, перетаскивание двигает её
целиком, инспектор показывает её как один элемент (общий замок + анимации на всех).
При наведении на члена группа обводится пунктирной рамкой; в hover-плашке — «В группе
(N)». Копия группы (copy/paste, дубль) получает свою новую метку. Модель — логическая
(`tms.groupId` на членах, round-trip через `data-tms-meta`), без вложенности.

## Поиск (Ctrl+F)

Плавающий виджет ищет по: всем `slots.*`, `rangeSource.tag`,
`boolSource` (все теги групп), `valueTag`, тексту `cell_text`, `navigation`. Совпадения
подсвечиваются амбер-ореолом, текущее — насыщенный оранжевый, паном
центрируется в viewport (если за пределами). Enter/F3 — следующее,
Shift+Enter/F3 — предыдущее, Esc — закрыть.

## Холст: порты по ховеру

Порты ячеек по умолчанию скрыты, проявляются при наведении на ячейку
(или когда она выделена) — наводишь на элемент, видишь куда тянуть провод.
Чистый CSS (`.joint-element:hover` / `.tms-selected`), без JS.

## Холст: поворот и отражение символа

Выделенный символ можно **повернуть** (overlay-кнопки ↺/↻ или `R` / `Shift+R`, шаг
90°) и **отразить** по горизонтали/вертикали (overlay-кнопки flip или `Shift+H` /
`Shift+V`). Отражение зеркалит и картинку, и позиции портов — подключённые провода
следуют за ними; работает поверх поворота (кнопка задаёт экранную ось независимо от
угла). Хранится в `tms.flipH`/`flipV`, переживает round-trip. Недоступно для
`noRotate`-стенсилов (text/value/bus/pi) и заблокированных.

## Холст: порядок наложения (слои)

Когда символы перекрываются, порядком управляет контекст-меню → **«Порядок»**: на
передний план / выше / ниже / на задний план (применяется ко всему выделению).
Провода всегда остаются позади символов и в переупорядочивании не участвуют.
Порядок переживает round-trip (`meta.z`).

## Холст: врезка и срастание проводов

**Врезка** — drop стенсила с **≥2 портами** из палитры на провод разбивает его
на два сегмента с проходом через элемент: исходный линк переиспользуется как
`source→cell.in`, добавляется `cell.out→target` с клоном анимаций; элемент
наследует диапазоны/булево провода (но его собственная конфигурация приоритетнее —
наследуется только то, чего у него нет). Во время drag над проводом превью липнет
к линии и поворачивается под угол врезки.

- Угол врезки (`utils/wireSplice.js` → `spliceRotation`): пара проходных портов
  выравнивается вдоль **локального сегмента** провода в точке врезки (касательная
  `wireDirAt`, не линия центров — rightAngle-роутер гнёт провод). Для 2-портовых
  из двух вариантов (±180°) сторона курсора выбирает разворот: на горизонтальном
  сегменте курсор выше → по часовой, ниже → против; на вертикальном слева → как
  есть, справа → 180°.
- Выбор пары портов (`pickPassThroughPorts`) — тоже вдоль локального сегмента.
- Ручные изломы провода распределяются по сегментам относительно точки врезки
  (по длине вдоль пути): что было до неё — остаётся на первом сегменте, что после
  — переезжает на второй.

Вся геометрия/топология врезки и превью живёт в `composables/useWireSplice.js`
(чистые функции — в `utils/wireSplice.js`).

**Срастание** — удаление **одного** элемента, через который проходят ровно
**2 провода к 2 разным соседям**, объединяет их в один (вместо разрыва): выживший
линк перецеливается на дальний конец второго ещё до удаления (иначе каскад
JointJS снёс бы оба). Логика — `utils/wireSplice.js` → `planWireBridge`;
применяется в `useCanvas.deleteItems` (через него идут все пути удаления: Del,
контекстное меню, оверлей-кнопка, инспектор). Изломы обоих проводов сшиваются в
один список (с учётом порядка и реверса). В multi-select срастание НЕ делаем —
туда авто-попадают мостовые провода между ячейками, сохранять нечего.

## Холст: ручные изломы провода

У выделенного провода доступен тул `linkTools.Vertices`: drag по линии создаёт
излом, drag по излому двигает маршрут, double-click добавляет точку,
`redundancyRemoval` убирает излом, легший на прямую между соседями. Изломы
снапятся к сетке (`change:vertices`-хендлер) — край не отрывается от линии,
которую держит на сетке `gridRightAngleRouter` (snap-обёртка над `rightAngle`).
Роутеру нужен `useVertices: true`, иначе `rightAngle` игнорирует изломы.
Эндпоинт-ручки реконнекта рендерятся **поверх** vertex-adding обёртки (порядок
тулов), иначе клик у конца провода добавлял бы излом вместо перемещения. Изломы
переживают round-trip через `data-tms-meta`.

## Холст: ресайз шины

Шина (`cell_bus`) тянется за edge-хэндлы. Резайз через нативный
`cell.resize(w, h, { direction })` (`useBusResize`): `direction:'right'` держит
левый край, `'left'` — правый. Ширина снапится к `BUS_PORT_SPACING` (20) — один
шаг = один слот порта. При резайзе **влево** origin уезжает, поэтому порт-рефы
подключённых линков сдвигаются на число слотов (`top_i → top_(i+k)`) — порты не
пересоздаются, абсолютные позиции подключённых проводов сохраняются.

**Сжатие** прижимает провода к крайнему существующему слоту (с обеих сторон
одинаково): исчезнувший слот означает несуществующий порт, а провод на нём после
перезагрузки уехал бы в центр шины. Ничего не удаляется, отмена — `Ctrl+Z` вместе
с ресайзом.

## Экспорт

`exportProject(graph)` собирает:

- **view.svg** — целостный SVG с inline `<style>` для animation-классов.
  На каждой ячейке `id="animation-{stencilId}-{animId}"` + `data-tms-meta`
  (JSON для round-trip'а). cell_value сохраняет рантайм-конвенцию
  `id="animation-cell-{tag}"`. Провода — `<path id="animation-wire-{shortLinkId}">`.
- **animations.json** — мапа `id → card` для WebScada-рантайма.

cellId/linkId = JointJS UUID, стабилен между сессиями. Если у ячейки есть
`navigation`, animation-entry получает поле `"navigation": "view_id"` —
рантайм откроет указанную view при клике.

CSS в SVG:

- `*:not(text)` для `stroke` — текст не перекрашивается
- opt-in классы заливки: `.tms-range-fill` (диапазоны/off) и `.tms-state-fill`
  (цвет состояния, замкнутые фигуры stateful-стенсилов)
- `.animation-off` (slate-500) — поверх классов диапазонов
- `.animation-hidden { display: none }`
- `[data-tms-stencil="..."].animation-off .animation-hidden { display: initial }`
  — генерится для каждого стенсила с `quality: true` (cell_qk / cell_qr /
  cell_qf). При bad-качестве показываем обе позиции рычага одновременно:
  «данные ненадёжны, не врём про конкретное состояние»

### Quality-биндинги

Для стенсилов с флагом `quality: true` в stencil.json (cell_qk / cell_qr /
cell_qf) exporter автоматически генерирует биндинг по каждому привязанному
тегу с `source: 'quality'` и кейсом `[0, 191] → addClass: animation-off`.
Рантайм при bad/uncertain quality (< 192) красит ячейку серым; CSS-override
выше показывает обе позиции рычага.

## Round-trip

`view.svg` каждой формы открывается обратно — `projectLoader` читает
`data-tms-meta` и восстанавливает JointJS-граф. Один файл для рантайма и для
редактирования.

## Проект (формы + библиотека)

IDE работает с **проектом** — набором форм (схем) + библиотекой стенсилов.
Открыта одна форма; формы — дерево (навигатор в левой панели над палитрой; клик
по узлу → форма на холсте). Иерархию узлов (из `hierarchy.json`) можно
перестраивать перетаскиванием; она — метаданные редактора (на экспорт SVG и
рантайм не влияет). Состояние проекта (формы пер-id, активная, теги, дерево)
хранится в IndexedDB и переживает перезагрузку. Имя проекта = имя открытого
`.zip` (без расширения) — показывается в топ-баре у логотипа и используется как
имя файла при экспорте. Статус справа в топ-баре показывает единственное
состояние — «не сохранено» (браузер не смог записать в IndexedDB, риск потери
работы); в норме полоса пуста. Есть ли правки, не попавшие в `.zip`, видно по
амбер-точке на кнопке «Экспорт». Успешный автосейв молчит — кричим только про
ошибку записи.

Если хранилище **не прочиталось** при старте (браузер отказал в доступе, битая
транзакция), приложение не считает это «пустым проектом»: автосохранение
выключается целиком, показывается ошибка с просьбой перезагрузить страницу, а
данные в IndexedDB остаются нетронутыми — иначе пустой холст затёр бы проект.

- **Формы** — дерево в левой панели: «+» в шапке создаёт пустую (падает
  последним узлом в корень), кнопка-копия дублирует форму (`<id>_copy`, копия
  встаёт сиблингом и открывается), карандаш у строки — переименование, × —
  удаление (единственную удалить нельзя), **drag-and-drop** переносит/вкладывает узлы
  (линия между строками = переставить, подсветка узла = вложить внутрь; своё
  поддерево — недоступная цель). Формы вне дерева показываются группой «Без
  иерархии», узлы на несуществующую форму — битыми. Имя формы = имя папки при
  экспорте = цель навигации, поэтому переименование заодно чинит ссылки
  `tms.navigation` на старое имя во всех формах.
- **Открыть проект** (`Ctrl+O`) — выбрать **.zip**-архив проекта (файловый picker,
  File System Access). Раскладка внутри: `forms/<id>/view.svg` → формы,
  `library/<id>/{stencil.json,shape.svg}` → стенсилы, `taglist.csv` → теги,
  `hierarchy.json` → дерево форм. Стенсилы из бандла регистрируются в рантайме сразу
  (форма рисуется без ожидания reload): новые (нет в реестре) и **изменённые** —
  чья версия в бандле отличается от реестра (правка заливки/анимации), иначе
  правка «слетала» бы на встроенную версию. Их оверрайды пишутся в IndexedDB
  (переживают reload в проде); файлы в `definitions/` дописываются dev-плагином
  (бонус dev-режима). Стенсилы, которых нет ни в базе, ни в бандле,
  попадают в предупреждение. Пустые формы (заготовки, цели навигации) сохраняются
  — отбрасывается только битый SVG. Если запись в IndexedDB не прошла целиком
  (квота), импорт сообщает об этом и не перезагружает страницу.
- **Экспортировать проект** (`Ctrl+S`) — скачивание одного **.zip** (той же
  раскладки, имя файла = имя проекта): по форме `view.svg`+`animations.json`, используемые стенсилы в
  `library/`, `taglist.csv`, дерево форм `hierarchy.json`. Геометрия проводов
  снимается с реально отрисованного paper (формы прогоняются через холст под
  оверлеем).
- **Стенсилы — физические файлы** в `src/stencils/definitions/` (Vite-glob).
  Персистентный реестр — статичный glob; браузер сам в исходники писать не может,
  поэтому запись/удаление идут через dev-плагин (`vite.config.js`): импорт проекта
  и редактор стенсилов шлют `POST /__stencils/import`, удаление из палитры —
  `POST /__stencils/delete`. `registerStencil` / `unregisterStencil` держат реестр
  в актуальном виде до reload (реактивно через `registryVersion` — палитра
  обновляется без перезагрузки). Персистентность правок вне dev держит
  `stencilOverrides` (IndexedDB): импорт/редактор пишут туда изменённые и новые
  стенсилы, старт поднимает их в реестр. Сравнение «изменился ли» — по
  `stencilSignature` (устойчиво к порядку полей); неизменённые встроенные не
  дублируются.
